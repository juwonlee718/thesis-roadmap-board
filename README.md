# 샤논 · 졸업논문 진행 보드

학생의 연구계획 초안부터 지도 상담, 면담, 교수 승인, 최종논문 파일 심사까지 연결하는 브라우저 데모입니다. 학과 조교가 절차·순서·마감과 공지를 관리하면 학생 로드맵과 캘린더가 같은 데이터로 바뀝니다.

## 실행

Node.js 22.12 이상인 22.x 또는 24.x, npm이 필요합니다. 검증 환경은 Node 24.17.0입니다.

```bash
npm ci
npm run dev
```

[로컬 시작 화면](http://127.0.0.1:3000)에서 학생·교수·행정실 역할을 선택합니다. 헤더에는 역할 탭이 없으며, ‘역할 선택으로’를 누르면 랜딩으로 돌아갑니다. 이름은 샤논, 색상은 절제된 네이비·블루·화이트이며 공식 대학 서비스나 로고를 표방하지 않습니다. `app/icon.svg`가 파비콘입니다.

```bash
npm run build
npm run start
```

Next.js App Router + TypeScript + Tailwind CSS + Zustand persist. 서버 DB, 로그인, 외부 API, API 키, `.env` 없이 실행합니다. 기본 Next.js 설정으로 빌드할 수 있으며 공개 배포는 하지 않았습니다. 이전 `dist/` 정적 프로토타입은 보존되어 있지만 새 앱 실행 경로가 아닙니다.

## 현재 역할과 흐름

### 학생

- 주전공·복수전공에 맞는 로드맵, 전공별 안내, 통합 마감 캘린더, 가장 급한 다음 단계, 같은 주 마감 겹침을 확인합니다.
- 교수 선택 없이 연구 주제 또는 계획만 **초안 저장**할 수 있습니다. 새로고침·역할 전환 후 복원됩니다.
- 연구 주제와 계획을 작성해 사이트 안에서 **지도 요청**을 보냅니다. 별도의 ‘교수 컨택 완료’ 체크는 없습니다.
- 교수의 면담 요청·수정 요청·반려 피드백을 확인하고, 수정·반려 후 재신청합니다. 면담 요청 중에는 교수가 같은 신청에서 후속 결정을 내립니다.
- 교수별 졸업논문 수강 데이터가 있는 전공은 수강한 교수와 자동 연결됩니다. 행정실이 다시 배정하지 않습니다.
- 앞선 절차를 마치면 **최종논문 파일**을 제출합니다. 교수 수정 요청·반려 후 수정본을 재제출하고 이전 버전과 피드백을 확인합니다.

### 교수

- 모든 교수 화면에서 지도 정원을 설정합니다. 현재 배정 인원보다 작거나 소수·음수인 정원은 허용하지 않습니다.
- 대기·면담 요청·수정 요청 상태에서 승인/면담 요청/수정 요청/반려를 처리합니다. 면담 요청 후에도 승인·반려 버튼이 계속 제공됩니다.
- 교수 승인 즉시 해당 전공의 지도교수 단계가 완료됩니다. 이전 행정실 확정 검토 게이트는 제거했습니다.
- 배정된 학생의 실제 논문 파일을 내려받고 승인·수정 요청·반려합니다. 승인 시 해당 전공의 논문 제출·심사결과 단계가 완료됩니다. 다른 전공은 유지됩니다.

### 행정실(학과 조교)

- 이름·학번 검색, 학과 필터, 졸업학기·초과학기·재학 필터와 10/20명 페이지네이션으로 **소속 학생 전체**를 조회합니다. 전공 설정 전이나 논문 면제 학생도 명단에 포함합니다.
- 학생별 상세를 열어 전공 진행 상태, 연결된 교수, 최종논문 심사 상태를 확인합니다.
- 학과 절차의 단계명·설명·순서·마감·서류·제출방법·서식·문의처를 편집하고 단계를 추가합니다. 저장하면 학생 로드맵과 캘린더에 반영됩니다.
- 단계 ID를 유지하여 기존 완료 이력이 보존됩니다. 현재 단계는 새 순서에서 첫 미완료 단계로 다시 계산합니다. 지도교수→최종논문→결과의 의미적 순서는 지켜야 합니다.
- 다른 탭이 편집 중인 학과 절차를 바꾸면 덮어쓰지 않고 충돌을 알립니다. 최신 절차를 명시적으로 불러와 다시 편집합니다.
- 학과 공지 제목과 내용을 등록하면 해당 전공 학생 화면에 표시됩니다.
- 교수 정원과 변경 이력을 조회합니다. 명단 등록·내보내기는 준비 중이며, 행정실 교수 배정 버튼과 확정 검토 버튼은 없습니다.

## 가상 데이터와 가정

모든 인물·절차·날짜·수업·공지·문의처는 합성 데이터입니다. 공식 링크는 모두 **예시 링크(가상)**, 출처는 **예시 데이터**로 표시합니다. 실제 학과 정보를 수집하지 않았습니다. 문의 주소는 발송 불가능한 `example.invalid` 예약 도메인입니다.

| ----------- | --------------------------------- | ------------------------------------------------ |

| 가상학생 02 | 사회학 주전공 + 심리학 복수전공   | 초과학기, 미신청                                 |
| 가상학생 03 | 기계공학 주전공 + 사회학 복수전공 | 재학, 수강 교수 자동 연결, 사회학 면제           |

| 가상학생 05 | 사회학 주전공                     | 초과학기, 가상교수 05에게 마감 전 접수한 대기 건 |

학과별 교수는 2명씩 총 6명입니다. 01–02 심리학, 03–04 기계공학, 05–06 사회학입니다. 가상교수 05는 정원 1명/배정 1명으로 마감이며, 다른 교수는 기본 5명입니다. 모든 교수의 정원을 설정할 수 있게 모든 가상 학과에서 정원을 사용합니다. 이미 수강 신청된 수업은 교수 정원 변경으로 해제하지 않습니다.

주전공/복수전공 논문 요건은 심리학·기계공학 모두 필수, 사회학 주전공 필수·복수전공 면제입니다. 기존 AGENTS.md 및 docs 원본은 수정하지 않았으며, 상충하는 예전 ‘외부 컨택’, ‘행정실 배정/확정’, ‘파일 미제공’, ‘정원 일부 학과만 설정’ 규칙은 이번 사용자 요구를 우선했습니다. docs/admin.md는 저장소에 없습니다.

## 저장과 파일 제한

- 동일 브라우저·동일 출처의 `localStorage`(`thesis-board-v1`, 스키마 version 2)에 상태와 파일 실제 내용을 저장합니다. 다른 탭은 storage 이벤트로 즉시 반영합니다.
- 기존 version 1 저장 데이터는 학생·신청 기록을 보존하고 수강정보·학적·새 절차 데이터를 채우며 마이그레이션합니다.
- 파일은 PDF/DOCX/TXT, 파일당 최대 **1MB**입니다. 파일명만 기록하는 방식이 아니라 Base64 원문을 저장하여 교수 화면에서 원래 내용으로 다운로드됩니다.
- 브라우저 저장 용량을 넘으면 제출을 거부하고 오류를 표시합니다. 저장 실패 시 화면의 상태도 변경하지 않습니다. 여러 큰 파일을 지속 보관하는 용도로는 서버 저장소가 필요합니다.
- 같은 브라우저 안의 역할 시연만 지원합니다. 실제 교수의 다른 기기까지 전송되지는 않습니다. 인증, 기기 간 공유, 서버 저장소, 실제 학사 수강 연동은 미구현입니다.
- 학과 편집은 충돌을 감지하지만 일반 동시 편집은 마지막 저장이 우선입니다. **데모 초기화**는 파일·이력·공지·학과 편집을 포함해 seed로 복원합니다.
- 최종논문 이외 서류는 제출 상태만 기록합니다. 실제 수강신청과 정규 성적 처리는 합성 데이터로 표현합니다.

## 사용자 테스트 질문

1. 지금 가장 먼저 해야 할 일과 마감은 무엇인가요?
2. 연구 주제만 준비된 상태에서 저장할 수 있나요? 외부에서 교수에게 먼저 연락해야 하나요?
3. 면담 요청을 받은 뒤 교수와 학생은 각각 무엇을 할 수 있나요?
4. 수업 전공의 지도교수는 어떻게 결정되었나요?
5. 제출한 논문이 수정 요청을 받으면 어디서 이유를 보고 어떤 파일을 다시 제출하나요?
6. 조교가 마감일을 바꾸면 학생 화면의 어느 부분이 달라지나요?
7. 초과학기인 학생만 찾아서 특정 학번의 진행 상태를 확인할 수 있나요?

진행자는 첫 답변, 소요 시간, 클릭 경로와 막힌 지점을 기록합니다. 참여자 5명 중 4명 이상 다음 할 일 정답, 전공 입력 후 1분 내 절차 이해 등 사람 평가 결과는 아직 없습니다.

## 학과 데이터 교체·편집

초기값은 `data/departments/*.ts`, 등록 목록은 `data/departments/index.ts`, 가상 수강/교수/학생은 `data/seed.ts`에 있습니다. 실제 공지 자료를 제공받으면 그 내용으로 초기 데이터를 교체합니다. 사용자가 제공한 실제 URL만 공식 링크에 넣고, 없으면 가상 링크 표시를 유지합니다.

화면에서 조교가 편집한 절차는 localStorage에 저장되어 seed보다 우선합니다. 초기 파일을 교체한 뒤 기존 브라우저에는 데모 초기화를 해야 새 seed가 반영됩니다. 각 단계는 고유한 ID와 처리 종류(advisor/course/submission/thesis/result)를 갖습니다. 기존 단계 ID와 처리 종류를 바꾸거나 삭제하지 않고, 이름·날짜·순서를 편집합니다. 추가 단계는 서류 제출/수업 확인으로 생성하며 적절한 위치로 이동합니다. 모든 학과에 지도교수·최종논문·심사결과 단계가 하나씩 필요합니다. 마감일 검증은 유효한 ISO 날짜를 사용하며 특정 학기로 고정하지 않습니다.

## 검증

```bash
npm run test
npm run typecheck
npm run build
npx playwright install chromium
npm run test:e2e
```

E2E는 개발 서버와 충돌하지 않도록 3100 포트에서 프로덕션 서버를 자동 실행합니다. 다른 서버가 사용 중이면 중지 후 실행합니다. 단위 테스트가 누락정보 fixture를 만들므로 테스트 순서를 유지합니다. Playwright는 PC 1440px와 모바일 390px에서 실행합니다. 캡처는 `output/playwright/*-shannon-*.png`, 실행 보고서는 `playwright-report/index.html`에 생성됩니다. 예전 이름의 캡처는 이전 버전의 증빙으로 보존됩니다.

- 단위/데이터/저장 테스트: 전공·면제·수강 연결·다전공 긴급도·초안·면담 후 의사결정·정원·절차편집·공지·실제 파일 원문·재제출·담당교수 확인·저장 실패 원자성.
- E2E: 브랜드/파비콘/랜딩, 초안 복원, 면담 후 승인·반려, 모든 교수 정원, 조교 수정·공지의 별도 학생 탭 반영, 128명 합성 명단 검색·필터·페이지네이션, 실제 다운로드 바이트 비교, 수정·반려·재제출·논문 승인.
